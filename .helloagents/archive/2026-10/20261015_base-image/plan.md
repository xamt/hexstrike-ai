# 镜像拆分 — 实施规划

## 目标与范围
执行用户已确认的双镜像设计。

## 架构与实现策略
Dockerfile.base 多阶段安装工具与 Python；按原分类拆分安装脚本，各类别使用独立只读绑定挂载及 APT 缓存。Dockerfile 仅引用 BASE_IMAGE、创建应用虚拟环境、安装过滤后的依赖、复制代码。Volatility3 使用专用环境和包装命令。Go 取消 GOBIN，按目标平台收集产物。

## 领域语言
基础镜像：工具及运行时；应用镜像：项目依赖、代码与启动配置。

## 完成定义
qaMode=standard；代码交付要求隔离边界、原版本保留、离线回归与审查通过。按用户最新要求，不再继续镜像测试；保留已经完成的 ARM64 证据，AMD64 完整镜像验收明确移交用户，不视为通过。

## 文件结构
Dockerfile.base、Dockerfile、docker/、tests/、DOCKER_BUILD.md、.dockerignore。

## UI / 设计约束
不适用。

## 风险与验证
滚动仓库缺失固定包、网络连接、跨架构编译、Python 命令覆盖。先离线测试后真实构建；不静默换版本。保留旧 Git 提交作为回退点。
