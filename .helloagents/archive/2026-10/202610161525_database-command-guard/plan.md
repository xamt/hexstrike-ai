# 数据库命令保护 — 实施规划

## 目标与范围
五类客户端接口保留查询、新增和更新，服务端真实拦截删除及高风险入口，不只更新说明。

## 架构与实现策略
统一策略异常及分派；SQL 独立词法模块与允许规则，Redis/MongoDB 按命令及子结构校验。validate_request 与执行器入口复用保护。HTTP 对策略拒绝返回403；参数错误维持400。无绕过参数、白名单外不执行。

## 领域语言
允许列表表示支持的保守查询/写入子集，不等于所有SQL或数据库命令；策略拒绝不同于数据库权限不足和执行失败。

## 完成定义
五接口危险样本拒绝且执行器未调用；普通查询及新增/更新样本保留；直接执行入口同样拒绝；qaMode=deep，重点关注词法绕过、嵌套删除、泄密和文档一致性。

## 文件结构
database_tools/policy*.py、SQL词法模块及contracts/http/runner；tests/test_database_policy*.py 与现有测试；共享契约、生成技能及DOCKER_BUILD.md。

## UI / 设计约束
不适用。

## 风险与验证
新增/更新可能触发数据库内部删除或覆盖已有数据，过滤不替代最小权限账号和受控网络，用户明确接受该边界。未知语法拒绝可能收紧兼容性，需明确列出。离线单元测试与独立审查，不将其说成数据库实测。回退不得静默关闭策略。
