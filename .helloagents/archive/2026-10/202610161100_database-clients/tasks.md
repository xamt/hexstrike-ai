# 数据库客户端镜像环境 — 任务分解

## 拆分原则
按可验证行为拆分；AFK 为离线开发，HITL 为用户自行进行的部署验收。

## 任务列表
- [√] 安装契约（AFK）：Dockerfile.base、docker 安装/验证脚本与相关 tests；五类客户端固定版本、双架构来源、版本记录和命令校验一致，原版本未变；47 项离线回归通过。
- [X] 数据库执行（AFK）：按用户最新要求撤回全部未提交执行器及相关测试。
- [X] HTTP/MCP/健康（AFK）：按用户最新要求撤回接口/健康实现，原服务和 MCP 文件与 HEAD 一致。
- [√] 文档与回归（AFK）：DOCKER_BUILD.md 保留四条独立架构构建命令、固定版本来源及边界说明；离线测试和 Shell 语法检查通过。
- [-] 双架构构建与真实连接（HITL）：按用户要求留给用户执行，不是本轮验收通过项。

## Codex /goal 执行入口
如用户显式启动 /goal，按本目录 tasks.md 通过 ~auto 执行 AFK 项，进入 ~qa；HITL 仍遵守不自动构建及连接数据库的边界。
